`unchangedAfterPublish` は破れます。`single` は `FENCE = false` なので、公開後でも別の実行が同じパスに書き込めます。

1. `collect("s1", 0, true, false)` で文書を作ります。`today = 1`、`items = {1}`、`pending = true` になります。
2. `deliver("s1", "r1")` で r1 が配信を受けます(`attempts = 1`)。
3. `check("r1")` で、status が `creating` のまま項目があるため、r1 は `selected` に進みます。`FENCE` がないので制作権は取りません。
4. `ackTimeout("r1")` で、r1 は ack 期限切れの orphan になり実行は続きます。`attempts < 2` なので `pending = true` に戻ります。
5. `deliver("s1", "r2")` で再配信を r2 が受けます。
6. `check("r2")` で、status がまだ `creating` なので、r2 も `selected` に進みます。
7. `writeScript("r1")`、`writeAudio("r1")` で、r1 が slot 0 に台本と音声を書きます。
8. `publish("r1")` で、`mayPublish` は常に true なので公開されます。`status = created`、`pubScript = "r1"`、`pubAudio = "r1"` になります。
9. `writeScript("r2")` で、r2 が公開済みの台本パスを上書きします。`scriptBlob[("s1", 0)] = "r2"` となり、`pubScript = "r1"` と食い違うので不変条件が偽になります。
