`unchangedAfterPublish` は破れます。`single` は `FENCE = false` なので、台本と音声は常にパス世代 0 に書かれ、公開は何も確かめません。公開した後でも、別の実行が同じパスを上書きできます。

反例の流れは次のとおりです。

1. `collect("s1", 0, true, false)` で番組を作ります。`pending = true`、項目のある日は {1}、`today = 1` です。
2. `deliver("s1", "r1")` で r1 が配信を受け、`attempts = 1` になります。
3. `check("r1")` は、status が `creating` で終端ではなく、項目もあるので `selected` に進みます。
4. `ackTimeout("r1")` で r1 は orphan になります。`respond` は失敗扱いで、`attempts < 2` なので `pending = true` に戻ります。r1 の実行自体は続きます。
5. `deliver("s1", "r2")` で再配信を r2 が受けます。`attempts = 2` です。
6. `check("r2")` は、status がまだ `creating` で `FENCE` もないので `selected` に進みます。これで 2 つの実行が同じ番組を制作している状態になります。
7. `writeScript("r1")`、`writeAudio("r1")`、`publish("r1")` を順に実行します。公開すると `status = created` になり、`pubScript = r1`、`pubAudio = r1` が記録されます。
8. `writeScript("r2")` で r2 が `scriptBlob[(s1, 0)]` を r2 で上書きします。公開時に記録した `pubScript = r1` と食い違うので、`unchangedAfterPublish` が偽になります。
