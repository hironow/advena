`unchangedAfterPublish` は破れます。`single` は FENCE が false なので、台本と音声のパスは世代 0 の 1 つだけです。公開後でも、別の実行がそのパスを上書きできます。

トレースの流れは次のとおりです。

1. `collect("s1", 0, true, false)` で文書を作ります。`storedDay` は 1、`items` は {1}、`pending` は true になります。
2. `deliver("s1", "r1")` で 1 回目を配信します。
3. `check("r1")` は `creating` のまま通過し、r1 は `selected` になります。
4. `ackTimeout("r1")` で r1 が orphan になり、`attempts` は 1 で上限未満なので `pending` が true に戻ります。r1 の実行そのものは続きます。
5. `deliver("s1", "r2")` で再配信が r2 に届きます。
6. `check("r2")` を通ります。status は `creating` のままで終端ではないので、r2 も `selected` になります。
7. `writeScript("r1")` と `writeAudio("r1")` で r1 が台本と音声を書きます。
8. `publish("r1")` は FENCE がないので何も確かめずに成功します。`status=created` になり、`pubScript` と `pubAudio` はどちらも "r1" になります。
9. `writeScript("r2")` は、r2 が公開前の確認を通過済みで `selected` のままなので実行できます。`scriptBlob[(s1, 0)]` が "r2" に書き換わります。

この時点で `scriptBlob[(s1, 0)]` は "r2" ですが、`pubScript` は "r1" のままです。公開後に公開 URL の先の内容が変わっているので、不変条件が偽になります。
