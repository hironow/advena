**`sameRun` is violated.** In module `single`, `FENCE = false`, so `slotOf` is always 0. Every run therefore writes the script and audio to the same path, `(s1, 0)`. `publish` checks nothing, so a second run that overwrites the files produces a published show whose script and audio came from different runs.

The key step: an `ackTimeout` puts `s1` back into a redelivery-pending state while `r1` keeps running. `r2` then picks up the same show and works on it in parallel.

1. `collect("s1", 0, true, false)`: `s1` becomes `creating`. Because `FIX_DAY` is on, `storedDay = 1`, `items = {1}`, and `pending = true`.
2. `deliver("s1", "r1")`: `attempts = 1`, and `r1` is `started`.
3. `check("r1")`: the status is not terminal and `items` contains `targetOf = 1`, so `r1` becomes `selected`.
4. `ackTimeout("r1")`: since `attempts = 1 < 2`, `pending = true`. `r1` becomes `orphan` but keeps running.
5. `deliver("s1", "r2")`: `attempts = 2`, and `r2` is `started`.
6. `check("r2")`: the status is still `creating`, so `r2` also becomes `selected`.
7. `writeScript("r1")`: `scriptBlob(s1, 0) = r1`.
8. `writeAudio("r1")`: `audioBlob(s1, 0) = r1`, and `r1` is `voiced`.
9. `writeScript("r2")`: `scriptBlob(s1, 0) = r2`.
10. `publish("r1")`: since `mayPublish` is always true, the status becomes `created` with `pubSlot = 0`.

Right after step 10, `status == "created"` holds, but `scriptBlob(s1, 0) = r2` and `audioBlob(s1, 0) = r1`. So `sameRun` is false.
