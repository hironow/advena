**`dayAsIntended` は成り立ちます。** 公開された番組の `pubDay` は、どの経路を通っても文書の `storedDay` と同じ値になるからです。以下で順に確かめます。

**1. `storedDay` は 0 にならない。**
`single` では `FIX_DAY = true` なので、`collect` は `storedDay` に `dayFor(arg, today)` を入れます。
- `arg = 0` なら `today` (1 以上) が入ります。
- それ以外は `arg` (1 以上) が入ります。

**2. 番組対象日と本来の日は、どちらも `storedDay` になる。**
`storedDay ≠ 0` なので、`targetOf(d, t) = d.storedDay` です。同じく `intendedDay(d) = d.storedDay` です。

**3. `storedDay` は作成後に変わらない。**
- `collect` を実行できるのは `status == "none"` のときだけです。
- いったん作られた文書が `"none"` に戻る操作はありません。
- `storedDay` を書き換える操作も `collect` 以外にありません。

**4. 実行が覚える日は `storedDay` である。**
- 実行が `day` を持つのは `afterCheck` で `pc: "selected"` になるときだけで、値は `targetOf(d, today) = d.storedDay` です。
- `deliver` には `pending` が必要で、`pending` は `collect` の後にしか立ちません。そのため `check` は必ず作成済みの文書を読みます。
- 番組は `s1` だけなので、実行が別の文書の日を持ち込むこともありません。

**5. 公開された番組の日は `storedDay` である。**
- `status == "created"` にするのは `publish` だけです。
- `publish` は `pubDay` に実行の `day` を入れます。4 よりこれは `storedDay` に等しくなります。
- `FENCE = false` なので、`skipped` や `failed` になった後でも公開は起こりえます。それでも入る値は同じです。

よって、到達できるすべての状態で `pubDay == intendedDay` が成り立ちます。
