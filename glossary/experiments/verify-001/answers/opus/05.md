**Verdict: violated.** `unchangedAfterPublish` breaks in `single`, the current code with every switch false.

**Why.** Without FENCE, every run writes the script and audio to the same path, slot 0. `publish` checks nothing. An ack timeout causes a redelivery, so a second run can be producing the same show at the same time. If that second run writes after the first run has published, the content behind the public URL changes.

**Trace:**

1. `collect("s1", 0, true, false)`: s1 becomes `creating` with `storedDay = 0`, `items = {1}` and `pending = true`.
2. `deliver("s1", "r1")`: `attempts` becomes 1 and r1 is `started`.
3. `check("r1")`: the status is not terminal and day 1 has items, so r1 becomes `selected` with day 1.
4. `ackTimeout("r1")`: `attempts` is 1, which is below 2, so `pending` becomes true. r1 becomes an orphan.
5. `deliver("s1", "r2")`: `attempts` becomes 2 and r2 is `started`.
6. `check("r2")`: the status is still `creating`, so r2 is also `selected`.
7. `writeScript("r1")` and `writeAudio("r1")`: r1 writes both blobs at slot 0.
8. `publish("r1")`: the status becomes `created`, and `pubScript` and `pubAudio` are both `"r1"`.
9. `writeScript("r2")`: `scriptBlob[(s1, 0)]` becomes `"r2"`, which no longer equals `pubScript = "r1"`. The invariant is false.
