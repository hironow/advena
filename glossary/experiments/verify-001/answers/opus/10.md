**`onePerDay` は破れます。**

`FIX_DAY = false` なので、`collect` は `dayTaken` を確かめません。そのため、同じ日に `arg = 0` で 2 つの番組文書を作れます。

`FENCE` の制作権 (世代番号とリース) は番組ごとに付きます。別の番組の公開は止めません。両方の番組が同じ日に制作されると、それぞれ番組対象日 1 で公開されます。

**手順**

1. `collect("s1", 0, true, false)`
   - s1 が `creating` になり、`storedDay = 0`、`items = {1}`、`pending = true` になります。
2. `deliver("s1", "r1")`
   - r1 が `started` になります。
3. `check("r1")`
   - 番組対象日は `targetOf` により today = 1 です。items に 1 があります。
   - FENCE により、s1 は `producing`、gen 1、リース有効になります。r1 は `selected`、day 1、gen 1 になります。
4. `writeScript("r1")` → `writeAudio("r1")` → `publish("r1")`
   - `mayPublish` は `producing` かつ gen 一致で真です。
   - s1 は `created`、`pubDay = 1` になります。r1 は `idle` に戻ります。
5. s2 で同じ手順を繰り返します。
   - `collect` の前提はすべて満たされます。s2 は `none` で、FIX_DAY が false なので `dayTaken` の制約はありません。
   - s2 も `created`、`pubDay = 1` になります。

最後の `publish` の直後、`pubDay == 1` の公開済み番組が s1 と s2 の 2 本になります。`onePerDay` は偽です。
