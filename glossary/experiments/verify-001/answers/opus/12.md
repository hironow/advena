**結論: 破れます (violated)。**

`single` では `FENCE = false` なので、台本と音声のパスの世代 (`slotOf`) は常に 0 です。どの実行も同じパス `(s1, 0)` に書きます。そして `publish` は何も確かめません。そのため、ack 期限切れで再配信が起きると、同じ番組を 2 つの実行が並行に制作できます。片方が公開した後に、もう片方が台本を上書きすれば、公開 URL の先の内容が変わります。

**手順:**

1. `collect("s1", 0, true, false)`: status は `creating`、`items = {1}`、`storedDay = 0`、`pending = true` になります。
2. `deliver("s1", "r1")`: `attempts = 1` になり、r1 は `started` になります。
3. `check("r1")`: status は終端ではありません。番組対象日 1 の項目があるので、r1 は `selected` になります。
4. `ackTimeout("r1")`: `attempts` は 1 で、`MAX_ATTEMPTS` の 2 より小さいので `pending = true` になります。r1 は orphan になりますが、実行は続きます。
5. `deliver("s1", "r2")`: `attempts = 2` になり、r2 は `started` になります。
6. `check("r2")`: status はまだ `creating` で項目もあるので、r2 も `selected` になります。
7. `writeScript("r1")` と `writeAudio("r1")`: 台本と音声のパス `(s1, 0)` はどちらも r1 の内容になります。
8. `publish("r1")`: `mayPublish` は真なので、status は `created`、`pubScript = pubAudio = "r1"` になります。
9. `writeScript("r2")`: r2 はまだ `selected` なので実行できます。`scriptBlob((s1, 0))` が `"r2"` になります。

最後の状態では、`scriptBlob.get((s1, 0)) = "r2"` で、`pubScript = "r1"` です。両者が一致しないので、`unchangedAfterPublish` は偽になります。
