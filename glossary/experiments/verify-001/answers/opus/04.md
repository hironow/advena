`noItemsNotFailed` が破れるには、`checkedNoItems` が真で、かつ `status == "failed"` の番組が必要です。そこで、どの操作が `status` を `"failed"` にしうるかを見ます。

- `collect` は `"creating"` にします。
- `afterCheck` (`check`) が設定するのは次のどれかです。
  - status をそのまま保つ (終端のとき、またはリース中の producing のとき)
  - 該当なしなら `TERMINAL ? "skipped" : d.status` (`single` では TERMINAL=false なので元の status のまま)
  - FENCE で `"producing"`
- `publishDoc` は `"created"` にします。
- 次の操作は `status` を変えません: `respond`、`deliver`、`writeScript`、`writeAudio`、`depFails`、`ackTimeout`、`kill`、`leaseExpires`、`midnight`、`stutter`。
- `"failed"` を設定するのは `sweep` だけです。ただし `sweep` には `SWEEP` というガードがあり、`single` では `SWEEP = false` です。そのため `sweep` は一度も実行できません。

`init` の status は `"none"` です。ほかに `"failed"` を書く経路はないので、到達可能などの状態でも `status != "failed"` です。したがって `checkedNoItems` の値にかかわらず、不変条件は常に真です。

```json
{"verdict": "holds", "trace": []}
```
