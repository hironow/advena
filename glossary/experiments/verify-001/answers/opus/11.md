**verdict: violated**

`single` では `FENCE = false` なので、`slotOf` は常に 0 です。台本と音声はどの実行でも同じパス `(s1, 0)` に書かれ、公開した後も別の実行が上書きできます。

1. `collect("s1", 0, true, false)`: `FIX_DAY` なので storedDay = 1 になります。items = {1}、pending = true、status = creating です。
2. `deliver("s1", "r1")`: attempts = 1 になり、r1 は started です。
3. `ackTimeout("r1")`: attempts 1 < 2 なので pending = true に戻り、r1 は orphan になります。実行そのものは続きます。
4. `deliver("s1", "r2")`: attempts = 2 になり、r2 は started です。
5. `check("r1")`: status は creating で終端ではありません。`FENCE` がないので制作権の確認もありません。項目が 1 日目にあるので、r1 は selected になります。
6. `check("r2")`: 同じ理由で r2 も selected になります。
7. `writeScript("r1")` と `writeAudio("r1")`: `(s1, 0)` の台本と音声は r1 が書いたものになります。
8. `publish("r1")`: 何も確かめずに status = created になり、pubScript = pubAudio = "r1" になります。
9. `writeScript("r2")`: r2 はまだ selected なので書き込めます。`scriptBlob((s1, 0))` が "r2" になります。

この時点で `scriptBlob.get((s1, 0)) = "r2"` で、`pubScript = "r1"` と一致しません。そのため `unchangedAfterPublish` は偽です。
