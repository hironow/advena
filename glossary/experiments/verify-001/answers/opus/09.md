**結論: `onePerDay` は成り立ちます (holds)。**

1. **`storedDay` は 0 にならない。** `FIX_DAY = true` なので、`collect` は `storedDay` を `dayFor(arg, today)` にします。`arg = 0` なら `today` (1 以上)、そうでなければ `arg` (1 以上) なので、`storedDay` は必ず 1 以上です。

2. **2 つの文書の `storedDay` は必ず違う。** `collect` には `not(dayTaken(dayFor(arg, today)))` というガードがあります。`dayTaken` は status が `none` でない文書をすべて見ます (`skipped` や `failed` も含む)。status は一度 `none` から外れると戻りません。また、`storedDay` を書き換えるのは `collect` だけです。

3. **公開時の `pubDay` はその文書の `storedDay` に等しい。**
   - `publishDoc(r, s)` は `runs.get(r).doc == s` を要求し、`pubDay` に `runs.get(r).day` を入れます。
   - 実行の `day` を設定するのは `afterCheck` だけです。そこでは同じ文書 `s` について `targetOf(d, t)` を使い、`storedDay ≠ 0` なので値は `storedDay` になります。
   - `deliver` で実行が `doc: s` から作り直され、`check` を経ないと `selected`、`scripted`、`voiced` には進めません。そのため、公開する実行の `day` は必ずその文書の `storedDay` です。
   - `FENCE = false` なので `mayPublish` は常に真ですが、それでも公開される `pubDay` は `storedDay` 以外になりません。

4. 2 と 3 から、`created` の文書の `pubDay` はすべて互いに違います。したがって、どの日についても公開済み番組は高々 1 本です。
