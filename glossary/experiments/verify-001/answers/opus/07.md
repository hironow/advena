**結論: `sameRun` は成り立ちます。**

`single` では `FENCE = true` なので、台本と音声のパスの世代は `slotOf(e) = e.gen` です。

1. **世代はどの実行にも別の番号が付く。**
   - 制作権を取るのは `afterCheck` の FENCE 分岐だけです。そこで `gen: d.gen + 1` とし、文書と実行に同じ新しい値を入れます。
   - 番組は `s1` の 1 つだけで、文書の世代は増える一方です。
   - そのため、ある世代 g を持つ実行は高々 1 つです。
   - さらに配信は最大 `MAX_ATTEMPTS = 2` 回です。`collect` は `status == "none"` のときしか動かないので、作り直しもありません。よって制作権の取得は高々 2 回で、gen ≤ 2 です。パスの世代は `SLOTS = 0..2` の範囲に収まります。

2. **パス (s1, g) に書くのは世代 g の実行だけ。**
   - `writeScript` と `writeAudio` は `slotOf(runs.get(r)) = runs.get(r).gen` のパスにだけ書きます。
   - 1 の理由で、そのパスに書くのはその世代を持つ唯一の実行です。

3. **公開が成功するのは、その実行が台本と音声の両方を書いた後だけ。**
   - `publish` は `pc == "voiced"` を要求します。この状態になるには、同じ実行が `writeScript` と `writeAudio` を両方済ませている必要があります。
   - 公開が成功すると `pubSlot` はその実行の gen になり、実行は `idle` に戻ります。
   - その世代を持つ実行は他にないので、公開後にパス (s1, pubSlot) を書き換える実行はありません。
   - 古い世代の実行がまだ動いていても、書くのは自分の世代のパスで、pubSlot とは別の場所です。

4. **公開以外の経路で `created` にはならない。**
   - `status == "created"` になるのは `mayPublish` が真のときの `publishDoc` だけです。
   - いったん `created` になると、その後の `check` は終端状態として何も変えずに戻ります。

以上より、`created` のとき `scriptBlob[(s1, pubSlot)]` と `audioBlob[(s1, pubSlot)]` は、どちらも公開した同じ実行の名前です。したがって `sameRun` は到達可能なすべての状態で成り立ちます。
