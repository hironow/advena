**結論: 破れます(violated)。**

`single` では `FENCE = false` なので、台本と音声は常に世代 0 の同じパスに書かれ、`check` は status を書き換えません。そのため ack 期限切れによる再配信を別の実行が受けると、2 つの実行が同じ番組を並行に制作でき、片方が公開した後にもう片方が同じパスを上書きします。

反例の流れ:

1. `collect("s1", 0, true, false)`: 1 日目に収集。`FIX_DAY` により `storedDay = 1`、`items = {1}`、`pending = true`。
2. `deliver("s1", "r1")`: `attempts = 1`、r1 が `started`。
3. `check("r1")`: status は `creating` で対象日 1 に項目があるので、r1 は `selected`。status は `creating` のまま。
4. `ackTimeout("r1")`: `attempts (1) < 2` なので `pending = true` に戻り、r1 は orphan になるが実行は続く。
5. `deliver("s1", "r2")`: `attempts = 2`、r2 が `started`。
6. `check("r2")`: status はまだ `creating` なので、r2 も `selected`。
7. `writeScript("r1")`: `scriptBlob[(s1, 0)] = "r1"`。
8. `writeAudio("r1")`: `audioBlob[(s1, 0)] = "r1"`。
9. `publish("r1")`: `mayPublish` は常に真。status が `created` になり、`pubSlot = 0`、`pubScript = "r1"`、`pubAudio = "r1"`。この時点では不変条件は成り立つ。
10. `writeScript("r2")`: `scriptBlob[(s1, 0)] = "r2"` となり、`pubScript = "r1"` と食い違う。ここで `unchangedAfterPublish` が偽になる。
