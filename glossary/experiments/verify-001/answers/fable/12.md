**結論: 破れます (violated)。**

`single` では `FENCE = false` なので、`check` は status を書き換えず、台本と音声は常に世代 0 のパスに書かれます。そのため、ack 期限切れで再配信された 2 つ目の実行が、1 つ目の実行の公開後に同じパスを上書きできます。

反例の流れ:

1. `collect("s1", 0, true, false)`: status は creating、項目は 1 日目にあり、配信待ちになります。
2. `deliver("s1", "r1")` → `check("r1")`: status は creating のままで、r1 は selected になります。
3. `ackTimeout("r1")`: 配信回数は 1 で上限 2 未満なので再配信待ちになり、r1 は orphan のまま実行を続けます。
4. `deliver("s1", "r2")` → `check("r2")`: status はまだ creating なので、r2 も selected になります。
5. `writeScript("r1")` → `writeAudio("r1")` → `publish("r1")`: status は created になり、`pubScript` と `pubAudio` はどちらも "r1" です。
6. `writeScript("r2")`: 世代 0 の台本が "r2" に上書きされ、`pubScript` の "r1" と食い違います。

最後の状態で status は created、`scriptBlob.get(("s1", 0))` は "r2"、`pubScript` は "r1" なので、`unchangedAfterPublish` は偽です。
