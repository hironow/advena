**結論: `dayAsIntended` は成り立ちます。**

理由は次のとおりです。

1. `single` では `FIX_DAY = true` なので、`collect` は `storedDay` に `dayFor(arg, today)` を保存します。`today >= 1` で、`arg` は 0 か `1..today` なので、`storedDay` は必ず 1 以上です。
2. `collect` は `status == "none"` を要求し、どの操作も `status` を `"none"` に戻しません。番組は `s1` だけなので、`storedDay` は一度決まると変わりません(他の操作は `{ ...d, ... }` で `storedDay` に触れません)。
3. `status` を `"created"` にするのは `publishDoc` だけで、そのとき `pubDay = runs.get(r).day` です。
4. 実行の `day` が設定されるのは `afterCheck` で `pc` が `"selected"` になる分岐だけで、値は `targetOf(d, t)` です。`storedDay != 0` なので、これは `today` に関係なく `d.storedDay` です。途中で `midnight` が挟まっても影響しません。
5. `"voiced"` に至る実行は必ずこの分岐を通っているので、公開時は `pubDay == storedDay` です。一方 `intendedDay(d)` も `storedDay != 0` なので `storedDay` です。

したがって、公開済みの番組では常に `pubDay == intendedDay` です。`FENCE = false` のため、`sweep` で `failed` になった後に別の実行が公開したり、2 つの実行が続けて公開したりすることはありえますが、その場合もどの実行の `day` も同じ `storedDay` なので、破れません。
