`onePerDay` は破れます。

現行コード（スイッチがすべて false）では、`collect` は同じ日に別の文書がすでにあるかを確かめません（`dayTaken` の確認は `FIX_DAY` のときだけ）。そのため、同じ日に `s1` と `s2` を続けて収集し、1 つの実行 `r1` で順番に制作・公開すると、どちらも `pubDay = 1` で `created` になります。

1. `collect("s1", 0, true, false)` で `s1` が `creating`、`items = {1}`、`pending` になります。
2. `deliver` → `check` で、`targetOf = today = 1` に項目があるので `r1` は `selected`、`day = 1` になります。
3. `writeScript` → `writeAudio` → `publish` で、`s1` が `created`、`pubDay = 1` になり、`r1` は `idle` に戻ります。
4. `s2` についても同じ日に同じ手順を繰り返すと、`s2` も `created`、`pubDay = 1` になります。

最後の `publish` の直後、日 1 の公開済み番組が 2 本になり、`onePerDay` が偽になります。
